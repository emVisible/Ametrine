# 2026-09-28 前端横向评估与第二轮润色

本轮首次拿到**真实运行环境**的可见性：`dev.sh` 用 tmux 拉起前端(:8000)、后端(:3000)、Milvus、Xinference，WSL 端口直通本机。此前两轮我只能读代码 + 用 mock 构建验证，这轮开始是**看着真实数据在改**。

一个环境要点：`vite.config.ts` 里 `basicSSL()` 无条件启用，自签证书会让部分浏览器/内嵌 WebView 直接拒绝加载（`ERR_CERT_AUTHORITY_INVALID`），而且换端口后 WSL 的新端口并不会自动转发到 Windows。已把 TLS 改为可关：`VITE_DEV_HTTPS=false pnpm dev` 走纯 HTTP（localhost 本身就是安全上下文，麦克风仍可用），默认行为不变。

## 1. 侧边栏：上一轮为什么没修对

上一轮我只修了「多个导航项同时高亮」这一个症状（`NavLink` 前缀匹配），但真正的问题是**分区结构错了**。实测 DOM 顺序暴露了它：

```
品牌 → 新建对话 → 对话/检索切换 → 主导航(概览/知识库/租户/用户管理/设置) → 会话搜索 → 会话列表(flex-1) → 用户
```

聊天控件压在应用导航**之上**，应用导航又夹在会话区中间；会话列表用 `flex-1` 撑满剩余高度，没有历史时就是一整片空洞。另外浅色下 `--c-accent-soft` 是 `#eeecfc`，active 项与 idle 几乎无法区分——实测计算值确认了这一点。

本轮改成四个语义分区，自上而下稳定：

```
品牌 → 主导航(概览/知识库/组织与权限/设置) → 对话区(标题+新建 / 模式切换 / 搜索 / 历史) → 用户+主题
```

- 主导航 `shrink-0`，对话区 `flex-1 min-h-0` 内部滚动：长列表滚动不再影响导航。
- active 态加**左侧 2px 强调条 + 强调色文字 + 加深底色**（`#eeecfc → #eae6fb`），三重冗余而不是只靠底色。
- 新建会话从一个大按钮降级为分区标题行的图标按钮，让「对话」这个分组自己承载它，减少一个视觉大块。
- 空态从居中大块文字改为紧凑一行，不再撑出空洞。

实测：`aside` 直接子元素恰好 4 个分区；每个路由下 active 导航项恒为 1。

## 2. 租户 + 用户管理 → 「组织与权限」

这两个页面原本各自是一个 CRUD 表，但它们回答的是同一个问题：**谁能检索到什么**。拆开导致授权动作要跨页跳转，而且租户的成员归属根本没法在租户页看到。

合并为 `/admin/access`，两个页签共享同一批数据源：

- **成员**：列表（角色 / 最近登录 / 累计 Token）→ 行点击进详情，详情内三段：基本信息（含角色变更，管理员提权需二次确认）、**知识库授权**（按库授予/撤销，读写态直接标出）、**租户归属**（逐租户加入/移出）。
- **租户**：列表（绑定知识库 / 成员管理）→ 「成员」按钮打开成员弹层，可添加、可移出。

关键取舍：成员详情里的「租户归属」必须**按租户真实取成员名单**（`useTenantMembers(tenantId)`）。上一轮发现的 `isInTenant = tenants.some(t => t.id === id)` 只判断租户存在，会让每个租户都恒显示「已加入」——那是同一类错误的模板，合并时没有沿用。

旧的 `Admin.tsx` / `AdminTenant.tsx` 已删除，路由与侧栏、概览页入口同步收敛为一个 `/admin/access`。

## 3. 色彩语义收敛：只有异常才着色

真实数据一上屏就暴露了 mock 阶段看不出的问题：

- 知识库列表 9 行，**9 个一模一样的绿色「可用」徽章**；
- 成员列表 7 行，**7 个一模一样的绿色「正常」**；
- 角色列里「经理」也是绿色，和相邻的状态绿并排，两个绿互相消解。

一整列同色徽章不携带任何信息，只是在抢注意力。本轮统一为：**正常态不着色，只标异常**（停用 / 已禁用 / 索引失败），并把角色色阶降为「仅管理员用强调色，其余中性」。删掉了两处纯冗余的状态列，把异常徽章内联到名称旁边。

## 4. 错误处理：从「写进正文」到「可行动提示」

实测真实 500 时发现的严重设计问题：错误被直接 `content: 检索失败：${msg}` **写进助手消息**，于是它 ① 污染会话历史并随 `chat_history` 回灌给模型 ② 持久化进 localStorage 再也清不掉 ③ 没有重试入口。而且用户看到的是 `HTTP 500`，完全不可行动。

本轮：

- `api/chat.ts` 增加 `describeStatus()`，把状态码翻译成中文可行动提示（500 明确指向「模型未加载或向量库不可用，检查 Xinference / Milvus」）。
- 新增 `ErrorNotice`，错误改为**独立 state**，渲染在消息流末尾，带重试按钮；失败的空气泡会被丢弃而不是留下一个空壳。
- 实测确认：只剩用户消息 + 一条带重试的提示，历史未被污染。

## 5. 顺带修掉的真实缺口

- **会话标题永远是「新对话」**：`sessionStore.addMessage` 里写好的自动命名逻辑根本没被调用——两个对话页都是直接 `setState` 覆盖 `messages`。已在共享 hook `useSessionMessages` 里补回唯一一处（首条用户消息前 40 字作为标题）。
- **RAG 选择器占位符歧义**：相邻两个 select 分别显示「知识库」和「先选知识库」，读起来像同一件事。改为「选择知识库 / 选择集合」。
- **Composer 三段横线**：上下文条原本带 `border-b`，加上工具条的 `border-t`，输入卡内部出现三条分隔线，看起来像表格。去掉上下文条的边框，收紧为输入框的题注。

## 6. 动效层

新增统一动效令牌与工具类，替换此前散落的 `transition-colors`：

- `--dur-fast/base/slow`（120/180/260ms）+ `--ease-out` / `--ease-in-out`；位移控制在 2–8px，够感知但不拖慢操作。
- `anim-page`（路由级淡入上移，挂在 `main` 的 `key={pathname}` 上）、`anim-pop`（弹层与错误提示）、`anim-fade`（遮罩）、`anim-toast`、`anim-stagger`（逐项入场，用 CSS 变量控制延迟，不需要 JS 计时）。
- `skeleton` 微光占位；`transition-ui` 统一过渡属性集合。
- 已有的 `prefers-reduced-motion` 兜底继续生效，动效总量被压到 0.01ms。

## 7. 工程层面的收敛

- `Tabs` 提为共用组件，`Settings` 与 `AdminAccess`（页签 + 用户详情弹层）三处手写 tab 逻辑归一。
- `queries.ts` 增补 `useUsers / useTenantMembers / useUserPermissions`，queryKey 统一挂到 `["access", …]` / `["knowledge", …]` 命名空间下，失效范围不再靠猜。
- 删除 `Admin.tsx` / `AdminTenant.tsx` 两个整页，`AdminAccess.tsx` 一页承接其全部能力。

## 8. 仍未做（诚实清单）

**工程**
- 没有测试与 lint 门禁：`eslint` 配置存在但 `pnpm lint` 未纳入任何流程；组件零测试。
- 没有路径别名，`../../` 相对导入仍在扩散（应配 `@/`）。
- 无错误上报/前端可观测性：查询失败只在界面上闪一下，没有任何留痕。
- `api/converstion.ts` 文件名拼写错误（conversation），且它和 `conversationAPI` 的边界与后端 `/api/conversation` 的 IDOR 问题纠缠，暂未动。
- 会话历史完全存在 localStorage（`chat-sessions`），后端 `Conversation/Message` 形同旁路；换浏览器即丢，且已污染的旧记录不会自愈。

**设计/视觉**
- 概览页左列在「最近会话」为空时仍偏空，两列高度不平衡。
- 暗色模式的强调色 `#9c8ff5` 在深色底上作为正文色时对比度偏低（作为徽章文字勉强可用），值得再校一轮 WCAG。
- 排版仍依赖用户本机是否装了霞鹜文楷；仓库不带字体（`*.ttf` 被 gitignore），跨机器观感不一致，需要一个明确的字体分发或纯系统栈决策。
- 图标尺寸仍有 `h-4.5`、`ml-6.5` 这类小数值，Tailwind v4 支持，但不如收敛到 4/5 两档整齐。
- 没有空态插画/引导图形（刻意保持克制，但概览页略单薄）。

**动效**
- 列表项进出没有 FLIP/高度过渡，删除会话是瞬间消失。
- 侧栏不可折叠，窄屏只有抽屉；没有命令面板（⌘K）这类现代前端常见入口。
